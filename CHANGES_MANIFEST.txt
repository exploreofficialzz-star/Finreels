lib/screens/content_search_screen.dart  (780 lines)
    Full in-app content search with the 2-column results layout from
    the design brief:
      LEFT  column — Shorts (9:16 portrait cards, tap → ShortsPlayerScreen)
      RIGHT column — Videos, Blogs, Books (16:9 cards, tap → correct screen)
    
    Search sources: all loaded videos/shorts + all books + blog articles
    from the cached RSS feeds (same scope as the Blogs tab, no extra
    network call if already cached).
    
    Matching: each query word is tested against title (×2 score), description
    (×1), and source/channel name (×0.5). Results scoring > 0 are included,
    sorted by score desc then by date desc within the same score.
    
    Debounced: waits 300ms after the user stops typing before running the
    search, so the screen never flickers while they're mid-word.
    
    Type badges: Video (blue), Short (purple), Blog (green), Book (amber)
    — same visual language as the reference screenshot.

lib/screens/home_screen.dart
    1. Search icon now opens ContentSearchScreen (in-app content search)
       instead of DiscoverScreen (category browser). DiscoverScreen is still
       reachable from its own navigation path.
    2. Added cacheExtent: 350 to the Videos tab ListView.builder — limits
       how far beyond the viewport Flutter renders cards. Without this bound,
       Flutter eagerly builds cards well off-screen, pre-warming WebViews for
       content the user may never reach and generating VisibilityDetector
       callbacks for every scroll frame. 350 ≈ one card height below the
       fold: enough for smooth scrolling without unbounded WebView creation.

lib/providers/feed_provider.dart
    _compute() for Videos and Shorts tabs now calls _dateMixed() instead of
    _roundRobin(). _roundRobin interleaved by channel-slot (newest from
    channel A, newest from channel B, channel C...) without caring about the
    actual upload dates across channels. _dateMixed():
      1. Sorts all videos globally by publishedAt descending (newest first)
      2. Gives category-channel videos a 3-day effective-date boost so the
         content the user explicitly selected surfaces above equally-old
         general content — without hiding genuinely newer general content
      3. Applies a diversity pass: no more than 2 consecutive videos from
         the same channel (excess videos are appended at the end)
    _roundRobin is kept (still used by the Blogs tab, which doesn't need
    date ordering since blog articles from BlogRssService are already sorted
    by their own publish date via _sortArticles).
    Added allFeedVideos and allBooksForSearch getters for ContentSearchScreen.

lib/widgets/inline_video_card.dart
    _onTap() now calls seekTo(Duration.zero) before play() on every tap,
    including the pre-warmed path. Guarantees the video always starts from
    the very beginning regardless of any position the iframe may have
    accumulated during pre-warm initialisation.
