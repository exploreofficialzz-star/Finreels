FinReels — Round 11
===================
7 files (1 new: notifications_screen.dart).

connectivity_overlay.dart — Tiny pill, no retry
  Single icon + short label, MainAxisSize.min (wraps content, never full-width).
  ~30px tall. Centered at top. No retry button — ConnectivityService already
  polls and the pill auto-dismisses when the stream emits online. Removed all
  retry state, _retrying bool, and _retry() method.

ad_block_overlay.dart — Belt-and-suspenders connectivity guard
  Now tracks _netStatus from ConnectivityService via a second stream listener.
  build() blocks the overlay when _netStatus != online, regardless of what
  AdBlockService last emitted. AdBlockService already resets to 'checking'
  when offline, but this catches any race condition between the two streams.

home_screen.dart — Refresh → Notifications bell
  Removed Consumer<FeedProvider> refresh button and its TweenAnimationBuilder/
  RotationTransition animation. Added a simple notifications_outlined bell icon
  that navigates to NotificationsScreen.

notifications_screen.dart — NEW
  Simple screen for notification preferences. Shows:
    • Enable/disable toggle (persisted via NotificationService)
    • List of channels being watched (ChannelData.eagerFor(selectedCategories))
    • OS permission request button with loading state
  No push server — all notifications are local WorkManager alerts.

content_search_screen.dart — Fix search not surfacing data
  Root cause 1: If the user typed a query before FeedProvider finished loading
  its first fetch (cold launch), allFeedVideos returned [] → instant "no results"
  screen, and nothing ever re-searched when the feed populated.
  Fix: _feedProvider.addListener(_onFeedChanged) — when state transitions from
  loading → loaded while a query is typed, _search() fires automatically.

  Root cause 2: "still searching" was indistinguishable from "genuinely nothing".
  Fix: Added _fetchingBlogs flag. While Phase 2 (blog RSS fetch) is in progress,
  the result count row shows a small spinner + "searching blogs…". _NoResults now
  accepts stillFetchingBlogs and shows a "still searching" variant instead of the
  final "no results" copy while blogs are pending.

  Also: context.read<FeedProvider>() replaced with _feedProvider (cached instance
  in initState) so _search() works correctly when called from _onFeedChanged
  (outside a build context).

rss_service.dart — Faster content loading
  HTTP timeout: 20s → 10s (YouTube RSS is fast; 20s allowed slow endpoints
  to hold up the whole refresh for far too long).
  Retry delays: [0, 1500, 5000] → [0, 600, 2000] ms (worst-case retry time
  cut from 6.5s to 2.6s while still protecting against transient failures).

feed_provider.dart — Faster content loading
  Channel stagger: 200ms → 50ms (total stagger for 12 channels drops from
  2.2s to 0.55s — the main visible reason "content loading is still poor").
